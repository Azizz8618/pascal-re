    # AGENTS.md

    ## Проект: компилятор ПАСКАЛЬ-МОНИТОР

    ### Общие сведения

    ПАСКАЛЬ-МОНИТОР — версия языка Паскаль для ЭВМ БЭСМ-6. Реализован в рамках мониторной системы "Дубна" в Вычислительном центре АН СССР. Язык полностью включает стандартную версию Паскаля. Основная цель — максимальная совместимость с уже работающими компиляторами Паскаля для БЭСМ-6 и Си-Ди-Си. Учтены реализации: ПАСКАЛЬ-АВТОКОД для БЭСМ-6, Паскаль для Си-Ди-Си 6000, Паскаль для Си-Ди-Си 3300 из Братиславы.

    Особенности мониторной системы "Дубна": присваивание значений переменным при загрузке через механизм данных и рассылок; связь переменных программы с общими областями памяти; раздельная компиляция программ на Паскале и Фортране и их совместное исполнение.

    ### Ключевые отличия от стандартного Паскаля

    #### Лексика и синтаксис

    Добавлено зарезервированное слово SELECT для оператора перебора, заменяющего вложенные IF.

    Символ подчёркивания "_" перед зарезервированным словом или идентификатором игнорируется.

    Первые 6 литер являются значащими в зарезервированных словах и идентификаторах.

    В идентификаторах разрешены буквы русского и латинского алфавитов.

    Эквивалентные ограничители: BEGIN и "(", DIV и "/", END и ")", NOT и "~", >= и "≥", <= и "≤", <> и "≠", OR и "V", AND и "Λ".

    #### Псевдокомментарии и управляющие режимы

    Комментарий, начинающийся с "(*=", задаёт управляющие режимы компилятора. Режимы разделяются запятыми без пробелов. Каждый режим может иметь знак "+" или "-".

    Основные режимы:

    E+ — экспорт процедур/функций для внешних программ. Не более 18 дополнительных входов.

    P+ — хранение идентификаторов процедур/функций и локальных простых переменных во время счёта. При аварии выдаётся авостная распечатка.

    T+ — динамические проверки: индексы, присваивания для отрезков, селекторы выбора. При ошибке печатается OVERRANGE IN и вызывается HALT; при P+ вызывается PASPMD.

    C- — отключение проверки соответствия типов. Использовалось для динамических массивов.

    R+ — операции отношения с вещественными значениями производятся с округлением. Порог в общей ячейке PASFUZZ, по умолчанию 1.E-6.

    M+ — оптимизация умножения целых чисел. M- допустим, только если все сомножители положительны.

    U+ — литеры с 73 (121) позиции до конца строки считаются комментарием. Максимальная длина строки 130.

    U- — запрещает некоторые нестрогие конструкции для совместимости с ПАСКАЛЬ-АВТОКОД: конструктор неупакованной записи, пустая правая часть присваивания A:=.

    A0—A3 — управление кодировкой строковых констант: Автокод ИТМ и БТ, АЦПУ-128, ИСО-ДУБНА, ТЕКСТ-ДУБНА.

    D — трассировка входов в процедуры/функции и отладочный вывод. Управляется двоичными разрядами n.

    K — размер памяти для глобальных переменных, выделяемой при использовании NEW. n*1024 слов.

    B — размер буфера последовательных паскаль-файлов в стеке. n*256 ячеек.

    L — управление печатью информации об исходной программе: 0 — никакой печати, 1 — печать восьмеричного относительного адреса и т.д.

    S — управление изображением внешних идентификаторов; S3, S4, S5 имеют специальное назначение.

    #### Заголовок программы

    Заголовок программы перечисляет все внешние информационные переменные. Синтаксис: PROGRAM <имя> (<параметр>[, <параметр>]...). Параметры — внешние файлы и общие переменные.

    Файловые параметры: <идентификатор-файла> [<указатель-файла-для-чтения>] [<дополнение-для-файла-типа-фортран>] [<дополнение-для-файла-типа-паскаль>].

    Дополнения для файла типа фортран: 50 или 51. 50 — ввод с перфокарт через READx, 51 — печать строки через PRINTB.

    Дополнение для файла типа паскаль: восьмеричное целое от 1000000B до 1743671743B, кодирующее HHHHTT3333 (число зон, математические номера направления и устройства, начальная зона).

    Файл OUTPUT обязателен в списке параметров и по умолчанию связывается с логическим номером 51.

    Файл INPUT необязателен и по умолчанию связывается с логическим номером 50.

    INPUT и OUTPUT считаются уже объявленными как TEXT = PACKED FILE OF CHAR.

    #### Константы и типы

    В строковых константах можно использовать восьмеричный эквивалент литеры после "_" или "=". Пример: '_060' = CHR(60B).

    Восьмеричные целые константы: суффиксы B, C, T. B — обычное восьмеричное целое; C — без порядка, справа; T — без порядка, слева.

    Стандартные имена: NIL — константа, ссылающаяся на адрес 74000B, совместима с любым указателем; FALSE, TRUE; INTEGER с максимальным значением 1777777777777777777777777777777777777777777777777777777777777777; REAL; CHAR от '_000' до '_377'; ALFA = PACKED ARRAY 1..6 OF CHAR; TEXT = PACKED FILE OF CHAR.

    #### Стандартные процедуры и функции

    ##### Файловые процедуры

    PUT(F) добавляет значение буферной переменной F^ в файл F. Требует BOF(F)=TRUE. Ошибки: NO EXTFILE TRACKS, NO LOCFILE TRACKS.

    GET(F) смещает позицию и присваивает значение компоненты буферной переменной F^. Требует EOF(F)=FALSE.

    RESET(F) возвращает файл в начало и присваивает буферной переменной первый элемент. Для файла с логическим номером 50 возвращает на начало текущей строки; для 51 запрещено.

    REWRITE(F) уничтожает текущее значение файла. EOF(F)=TRUE. Запрещено для внешнего файла с логическим номером 50.

    ##### Упакованные массивы

    PACK(A,I,Z) и UNPACK(Z,A,I).

    Если Z типа ALFA, то PACK(A[T],Z) эквивалентно PACK(A,T,Z), UNPACK(A[T],Z) эквивалентно UNPACK(Z,A,T).

    Проверка индексов не выполняется.

    ##### Динамическое размещение

    NEW и DISPOSE с формами (P), (P,T1..TK), (P=<выражение-целого-типа>).

    Автоматическая сборка мусора отсутствует. Динамические переменные размещаются в пуле данных.

    Пул данных: POOL с полями FREE, FML1, FMLK, DELIM, POOLS. По умолчанию POOLSIZE=4096, если используется NEW.

    При нехватке памяти: если переменная P в REXPORT, то P:=NIL, иначе печатается NO GLOBAL MEMORY.

    ##### База данных

    Процедуры: NEWD, OPEND, GETD, PUTD, MODD, DELD.

    NEWD заводит базу данных. OPEND открывает базу. PUTD, MODD, GETD засылают, модифицируют и выбирают информацию. DELD исключает элементы.

    Синтаксис PUTD/MODD/GETD: (<информация-для-обмена> [.<информация-для-обмена>]...).

    Информация: <имя-элемента-в-базе-данных> <переменная> [: <указатель-длины>].

    Переменная не должна быть файлом. При занесении имени элемента не должно быть в открытой области; при выборке или модификации — должно.

    При отсутствии указателя длины размер определяется компилятором по типу переменной. При выборке размер памяти для переменной должен быть не меньше размера выбираемого элемента.

    ##### Прочие процедуры и функции

    EXIT без параметра эквивалентна переходу на метку перед последним END текущей процедуры/функции. EXIT с параметром — переходу за оператор, соответствующий структурной метке.

    HALT: если программа транслировалась в режиме P+, вызывается внешняя процедура PASPMD, печатающая авостную распечатку; затем переход на последний END программы.

    MARIA(I,A): I — INTEGER, A — ALFA; после выполнения A получает '000345' в кодировке ИСО-ДУБНА. MARAI(A,I) выполняет обратное действие.

    STOP эквивалентна выполнению экстракода конца задачи 74; используется для закрытия внешних файлов.

    BESM(I) — системная процедура; целое выражение I трактуется как машинная команда ЭВМ БЭСМ-6, вставляемая в объектный модуль.

    Арифметические функции: SIN, COS, EXP, LN, SQRT, ARCTAN, ARCSIN.

    Функции ABS, SQR, SUCC, PRED.

    Предикаты: ODD, BOP (проверка конца файла), BOLN (проверка конца строки текстового файла).

    Функции преобразования типов: ROUND, TRUNC, ORD, CHR, PTR, REF.

    Дополнительные функции: CARD(X) — кардинальное число множества; MINEL(X) — порядковый номер минимального элемента множества, -1 если множество пустое.

    ##### Процедура WRITE

    WRITE(Ф, P1,...,PK) эквивалентно WRITE(Ф,P1);...; WRITE(Ф,PK).

    Для символьных файлов значения преобразуются в символьные строки.

    Параметры ДП и ДМ целого типа управляют шириной поля и длиной мантиссы. Для строк по умолчанию ДП равно длине строки. Если ДП меньше требуемого, преобразованное значение записывается без пробелов спереди.

    Переменная FIX управляет видом вывода: экспоненциальная форма или с фиксированной точкой. При ДМ>20 FIX:=TRUE, ДМ:=ДМ-20; при ДМ>10 ДМ:=10; при ДМ<1 ДМ:=1.

    ##### Процедуры чтения

    READ(Ф, П1,...,ПК) эквивалентно READ(Ф,П1);...; READ(Ф,ПК).

    READ(П1,...,ПК) эквивалентно READ(INPUT,П1,...,ПК).

    READLN(f, П1,...,ПК) эквивалентно READ(f, П1,...,ПК); READLN.

    READLN определяется как WHILE NOT BOLN(F) DO GET(F); GET(F).

    READ(Ф,П) при эквивалентности типов переменной П и элемента файла Ф эквивалентно П:=Ф^; GET(Ф).

    При чтении из символьного файла тип переменной П может быть строковым, CHAR, INTEGER, REAL.

    Чтение целого: процедура READI. Чтение вещественного: процедура READR с внешними INTLEN, INTSIGN, POWER.

    #### Дополнительные управляющие операторы

    SELECT: SELECT <условный-вариант> [; <условный-вариант>]... END. Условный вариант: <выражение> : <оператор>. Выражение логического типа.

    Структурные метки: каждый оператор может быть помечен (<структурная-метка>) <оператор>. Область действия — следующий за меткой оператор. GOTO M передаёт управление на начало оператора, помеченного M; EXIT M — за данный оператор. Структурные метки дают право каждому оператору на итерацию и завершение.

    #### Раздельная компиляция

    Внешние процедуры/функции описываются как <заголовок>; EXTERNAL;.

    Внешние фортран-подпрограммы/функции: <заголовок>; FORTRAN;.

    При вызове внешней паскаль-процедуры/функции необходимо соответствие статических уровней, числа параметров, их типов и внешних используемых переменных.

    При вызове внешней фортран-подпрограммы/функции фактические параметры, соответствующие формальным со словом VAR, передаются по ссылке, иначе — по значению. Это удобно при использовании внешних модулей языка ассемблера МАДЛЕН.

    Если процедуры/функции будут использованы как внешние в другой программе, их необходимо компилировать в режиме E+.

    #### Присваивание констант рассылкой

    Раздел DATA после программы. DATA <рассылка> [; <рассылка>]... END.

    Рассылка: <переменная> := <константа-с-повторением> [, ...].

    Константа-с-повторением: <обозначающее-константу-выражение> [; <повторитель>]. Повторитель — положительная целая константа. По умолчанию 1.

    Идентификатор DATA должен следовать непосредственно после заключительной точки программы. Раздел данных не обрабатывается, если после точки стоит пробел.

    При определении переменной в DATA не должны использоваться другие переменные или обращения к функциям. Обозначающее константу выражение состоит из констант, знаков операций и обращений к стандартным арифметическим функциям; знаки отношения недопустимы. Строковые константы в DATA не должны быть длиннее 6 символов.

    Пример DATA: PROGRAM TEST(OUTPUT); VAR M: ARRAY 1..1000 OF INTEGER; ... END. DATA M = 0 50, ROUND(AQR(3.14)) 50 M[5] = 51 M[100] = 0, 5, 7:2 END.

    #### Расширения определений типов и операторов

    В разделе описания типов разрешено использовать идентификаторы типов, которые будут определены позже. Такие идентификаторы называются предопределёнными.

    Если перед предопределённым идентификатором типа стоит "^", предопределяется идентификатор произвольного типа; без "^" — обязательно тип указателя.

    По окончании раздела описания типов, если не все предопределённые типы доопределены, печатается сообщение об ошибке с перечислением недоопределённых идентификаторов.

    Компилятор фиксирует ошибку, если предопределённый идентификатор типа указатель доопределяется другим типом.

    Взаимно рекурсивные процедуры должны быть переписаны с использованием FORWARD. Пример: PROCEDURE B(T:INTEGER); FORWARD; PROCEDURE A; BEGIN ... B(2) ... END; PROCEDURE B; BEGIN ... A ... END.

    Расширение оператора цикла: начальное значение в FOR можно опускать. Тогда оно считается равным минимальному значению соответствующего дискретно-упорядоченного типа, где ORD=1. FOR J TO 9 DO A(J) эквивалентно FOR J:=1 TO 9 DO A(J).

    Расширение операции MOD над множествами: A MOD B означает (A-B)+(B-A), то есть разностное сложение множеств. Реализуется командой "сравнение по модулю два" на БЭСМ-6.

    Определение типа массива: квадратные скобки можно опускать.

    ### Эксплуатация системы

    #### Трансляция

    Трансляция паскаль-программ в модуль загрузки мониторной системы "Дубна" вызывается картой *CALL *PASCAL.

    Модуль *PASCAL после предварительной работы вызывает основной блок компилятора PASC0MPL, написанный на языке ПАСКАЛЬ-МОНИТОР.

    Перед вызовом компилятора необходимо установить режим увеличенной памяти картой *CALL FICMEMOR и настроиться на считывание системной библиотеки Паскаля картой *PERSO:37230.

    Пример трансляции простой программы: *NAME T; *PERSO:37230; *CALL FICMEMOR; *CALL *PASCAL; PROGRAM TEST(OUTPUT); VAR I:INTEGER; BEGIN FOR I:=5 TO 8 DO WRITELN(I) END. *END FILE.

    Использование личной библиотеки: библиотека на 66g с 50g зоны, всего 10g зон. Карты: *NAME T; *PERSO:66050; * считывание личной библиотеки во временную; *PERSO:37230,CONT; *CALL FICMEMOR; *CALL PASCAL; текст программы; *CALL PASHELP; Y; *TO PERSO:66050; *END FILE.

    #### Выполнение

    Выполнение паскаль-программ: подготовка информации для связывания внешних файлов, присваивание значений общим переменным, вызов модуля программы картой *CALL имя-модуля.

    Модуль загрузки паскаль-программы удовлетворяет соглашению о связях мониторной системы "Дубна": регистры 1, 2, 3, 4, 5, 6, 7, 15 сохраняются; возвращается стандартный режим выполнения команд.

    Пример трансляции и выполнения: *NAME TTT; *PERSO:37230; *CALL FICMEMOR; *CALL *PASCAL; PROGRAM T(OUTPUT); BEGIN WRITELN(77) END. *EXECUTE; *END FILE.

    #### Сервисная программа PASHELP

    PASHELP — транслятор сервисного языка. Разделы: управление компилятором, запуск паскаль-программ, генерация вектора констант, уборка стандартных имён, настройка буферных листов и трактов.

    Раздел управления компилятором: P <режим-печати> <начальный-адрес-загрузки> <адрес-вводного-файла>. Режим печати: 0 — выключить, 1 — только видеотон, 2 — только АЦПУ-128, 3 — оба. По умолчанию P 1 0 50.

    Раздел запуска паскаль-программ: R <идентификатор-программы> [+] [<режим-печати>] [<связывание-файла>]... Связывание файла: <идентификатор-внешнего-файла> <адрес-файла>. Адрес файла: 50 | 51 | 0. 0 — локальный файл. Не более 5 внешних файлов. Результат — модуль PROGRAM, который устанавливает режим вывода, связывает файлы и передаёт управление программе. Знак "+" вставляет экстракод конца задачи 62 для отладчика ОС ДИСПАК.

    Раздел генерации вектора констант: T <идентификатор-программы> <идентификатор-текстовой-константы>... Эквивалентен вызову транслятора с языка МАДЛЕН.

    Раздел уборки стандартных имён: Y. Удаляет из временного каталога имена, начинающиеся с R/ и PAS.

    Раздел настройки буферных листов и трактов: D <восьмеричное-число-буферных-листов> <восьмеричное-число-буферных-трактов> <восьмеричное-число-обмена-для-начального-тракта>. По умолчанию D 2B 20B 250000B.

    #### Организация диалога

    Вывод: при заполнении буфера вывода файла OUTPUT 51 (126 символов) или при выполнении WRITELN(OUTPUT) начинается процедура вывода буфера. Файл дополняется значением из общей переменной PASENDS*, содержащей CHR(12B). Символ CHR(0) служит концом выводимой информации на видеотон.

    Для вывода вызывается подпрограмма P/PRINT; начальный и конечный адреса в индекс-регистрах 10 и 11. P/PRINT выводит на видеотон или АЦПУ-128 в зависимости от разрядов общей переменной REXPORT.

    При работе с видеотоном первый вывод производит "приём с приглашением" WHAT= в коде АЦПУ-128. Ответы: пустая посылка — продолжать; T — выполнить экстракод конца задачи 74; P — вывод на видеотон и АЦПУ-128; T — только видеотон; Ln — установить число строк до следующего приглашения; другой ответ — экстракод конца задачи 62 и вывод только на видеотон.

    Ввод с видеотона: внешние процедуры PASBIND, PASADD, PASINP. PASBIND(F) обнуляет файл F через REWRITE, открывает приём с видеотона и записывает введённые символы в F. PASADD(F) добавляет информацию к файлу. PASINP(A[1],A[7]) вводит информацию в массив A. Управляющие символы видеотона не редактируют информацию, кроме ERASE, отменяющего ввод.

    #### Совместное исполнение модулей

    Пример с фортран-подпрограммой POWX, паскаль-программой NOPROG и ведущей паскаль-программой M.

    Фортран: SUBROUTINE POWX(X,Y,Z); X=Y**Z; RETURN; END.

    Паскаль: PROGRAM NOPROG(OUTPUT); (*E+*) PROCEDURE NULL(VAR X:REAL); BEGIN X:=0 END; FUNCTION LENGTH(X,Y:REAL):REAL; BEGIN LENGTH:=SQR(X)+SQR(Y) END; BEGIN END.

    Ведущая: PROGRAM M(OUTPUT); VAR A,B,C:REAL; PROCEDURE POWX(VAR T,P,S:REAL); FORTRAN; PROCEDURE NULL(VAR XX:REAL); EXTERNAL; FUNCTION LENGTH(X,YY:REAL):REAL; EXTERNAL; BEGIN WRITELN(A,B,C); POWX(A,B,C); WRITELN(A,B,C); NULL(A); WRITELN(A); WRITELN(LENGTH(B,C)) END .DATA A:=2.0; B:=3.0; C:=4.0 END. *EXECUTE. *END FILE.

    Паскаль-программа не должна вызывать другие паскаль-программы.

    #### Сервисные утилиты

    PASHELP, TIME, PULT, PASTPR, PASOUT, PASLIST, PASBIND, PASADD, PASINP, PASGOST7, PASFOR, XREF, TOPULT.

    TIME: программа PASTIME содержит точку входа TIME. При обращении печатает RUNT, REST, DIFF. В общей переменной TIMELD типа REAL запоминается время процессора.

    PULT: внешняя процедура PULT передаёт управление системе ПУЛЬТ.

    PASTPR: внешняя паскаль-процедура с одним параметром для печати слов в кодировке ТЕКСТ-ДУБНА. Перед вызовом должен быть оператор записи в соответствующий файл.

    PASOUT: внешняя фортран-процедура с двумя параметрами для вывода информации от адреса первого параметра до адреса второго.

    PASLIST: внешняя функция без параметров. Анализирует режим печати в мониторной системе "Дубна", возвращает 0, 1 или 2 для XNO LIST, XSTANDARD LIST, XFULL LIST.

    PASGOST7: позволяет запускать паскаль-компилятор из системы ПУЛЬТ, генерируя задачу или непосредственно в решаемой задаче. Если используется режим полной памяти, устанавливаемый *CALL PICMEMOR, указание литеры F обязательно.

    Для программ со строками более 80 символов или больших программ удобно загружать текст в кодировке АЦПУ-128 на барабан 27g (массив BUF системы ПУЛЬТ). Пример задания: NAME TRANSLATION FROM 27; *PERSO:37230; *CALL PASGOST7; *CALL FICMEMOR; *CALL PASHELP; P 2 0 20270000B; *CALL *PASCAL; *EXECUTE; *END FILE. Третий приказ перекодирует текст из АЦПУ-128 (конец строки — _175', конец текста — _172') в кодировку ИСО-ДУБНА.

    PASFOR и TOPULT обрабатывают стандартный вводной файл до карты /, обозначающей конец текстового файла. Генерируют выходной текст в файле RESULT, по умолчанию на барабане 27g с нулевого тракта. С помощью режимов R и F PASHELP можно настроить выходной файл на требуемое устройство.

    PASFOR — программа автоматического редактирования паскаль-программ для получения структурно-расположенного текста ("красивая распечатка"). Управляющий комментарий (*/F3*) преобразует короткие _ ( и _) в BEGIN и END. Комментарий (*/F4*) отменяет действие (*/F3*). Количество значащих позиций определяется управляющим режимом U.

    XREF — программа "перекрестные ссылки", обрабатывает текст паскаль-программы и печатает лексико-упорядоченную таблицу: шестизнаковый идентификатор и номера строк, где он встречается.

    TOPULT — программа перекодирует стандартный входной файл в файл RESULT из кодировки ИСО-ДУБНА в массив констант ПУЛЬТ, выравнивает позиции 73—80 и значащие пробелы.

    ### Ограничения и примечания для агента

    Проект исторический, для ЭВМ БЭСМ-6 и мониторной системы "Дубна". Современные агенты должны учитывать отсутствие автоматической сборки мусора, особенности пула данных и ограничения памяти.

    При генерации кода и диагностик следует учитывать управляющие режимы компилятора и псевдокомментарии.

    Для совместного исполнения с Фортраном важно соблюдать соглашения о передаче параметров: VAR — по ссылке, иначе — по значению.

    Для внешних процедур/функций, экспортируемых из Паскаля, необходимо компилировать в режиме E+ и следить за числом дополнительных входов.

    Сервисный язык PASHELP и утилиты (PASFOR, XREF, TOPULT) являются частью экосистемы; при описании сборки и запуска следует ссылаться на них.
